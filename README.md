# KVStore
Built to internalize LRU cache design by implementing it from scratch (hashmap + doubly linked list, no OrderedDict) and pushing it further with TTL expiry, thread safety, and crash-safe persistence, the way a real system like Redis would need.

An in-memory key-value store with LRU eviction, TTL expiry, thread-safety, and
periodic disk snapshotting — built from scratch in Python and exposed as a
REST API with FastAPI.

Built to demonstrate core data structure / systems engineering fundamentals,
not just library usage: the LRU cache is implemented manually with a hashmap
+ doubly linked list, not `collections.OrderedDict`.

## Live dashboard

Run the server and open `http://localhost:8000/` for a live view of cache
stats and stored keys, or `http://localhost:8000/docs` for interactive
Swagger API docs (auto-generated by FastAPI).

## Design

**Core data structure — `app/lru.py`**
- Hashmap (`dict[str, Node]`) → O(1) key lookup.
- Doubly linked list with sentinel head/tail nodes → O(1) insert, remove,
  and move-to-front, with no edge-case branching for empty/single-node lists.
- `get`: O(1) lookup + O(1) move-to-head.
- `put`: O(1) insert; O(1) eviction from tail if over capacity.
- TTL is stored as an absolute expiry timestamp per node. Expired keys are
  removed lazily on access (`get`) and can be swept proactively via
  `POST /admin/sweep` or the background snapshot loop.
- A single `threading.RLock` guards all mutations — safe for concurrent
  access across FastAPI's worker threads. Verified under concurrent load in
  `tests/test_lru.py::test_thread_safety_concurrent_writes`.

**Persistence — `app/persistence.py`**
- Every 10s (configurable), the current cache contents are dumped to
  `snapshot.json` via an atomic write-then-rename (crash-safe: readers
  never see a half-written file).
- On startup, the snapshot is reloaded, with any already-expired entries
  correctly excluded rather than resurrected.
- Deliberate tradeoff: this is periodic snapshotting (like Redis RDB), not
  a write-ahead log (like Redis AOF) — up to `interval_seconds` of writes
  can be lost on a crash, in exchange for zero per-write I/O overhead.

**API — `app/main.py`**
- `PUT /keys/{key}` — set a value, optional `ttl_seconds`
- `GET /keys/{key}` — fetch a value (404 if missing/expired)
- `DELETE /keys/{key}` — remove a key
- `GET /keys` — list all live keys, most-recently-used first
- `GET /stats` — hit rate, evictions, expirations, size
- `POST /admin/sweep` — proactively evict expired keys

## Run it

```bash
pip install -r requirements.txt
uvicorn app.main:app --reload
```

Then visit `http://localhost:8000/` (dashboard) or `http://localhost:8000/docs` (API docs).

## Test it

```bash
pytest tests/ -v
```

14 tests covering eviction order, recency updates, TTL expiry, thread
safety under concurrent writes, and snapshot save/load round-trips.

## Possible extensions

- Swap the single-process lock for a sharded-lock design to reduce
  contention at high concurrency.
- Add a write-ahead log for stronger durability guarantees.
- Expose `/keys` with cursor-based pagination for large stores.
